# RECOVERY-13 — Complete language content review (isolated)

PR #25 snapshot: 0dd9239bc28978e11f41c1c0f618c9662b291fe2. The review branch does not edit shipped locale files, WebView screens, Android services, user data, or central translations.

## Commands

From the repository root, with Node.js:

    node --test tests/language_review/*.test.cjs
    node tools/language_review/audit.cjs --out /tmp/df-language-review

Without --out, the auditor writes no reports, data files or user records; it prints a summary. With --out, it writes coverage.json, proposals.json and REPORT.md only in the selected directory.

## Measurement rules

- Explicit source string-catalog coverage is grouped by language, source module and screen. It is NOT full rendered-interface coverage.
- Runtime-assembled v21 dictionaries, v22 premium rows, localization 20 recovery, quick training and binary English/Arabic editors are inspected. Missing keys and likely English copies are reported separately.
- The analyzer scans HTML visible literals, attribute strings and JavaScript dialog literals for human-review candidates; these are not automatically proven defects.
- Arabic, Persian and Urdu are the RTL locales. Number symbols generated by the UI must remain ASCII 0123456789; never normalize user-written notes, tasks or arbitrary content.
- A null proposal means the actual translation is incomplete, not that English should be copied into the other language.
- Completeness of meaning, tone, grammatical cases and naturalness requires native-speaker review.
- A full 20-language on-device Android WebView run, accessibility review, screenshot comparison, and dynamic DOM evaluation remain necessary before any production approval.
