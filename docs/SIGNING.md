# Release signing

The release workflow (`.github/workflows/build_aab.yml`) signs only with a key that lives in
GitHub Actions Secrets. No key or password is stored in Git.

| Situation | Result |
|---|---|
| Four signing secrets present | AAB + APK signed with the upload key, certificate fingerprint printed |
| Secrets absent, branch build | Random one-off key; artifacts named `...-ci-throwaway`; never upload to Google Play |
| Secrets absent, `v*` tag | Build fails; no release is published |

## Secrets

`DEEPFOCUS_KEYSTORE_B64`, `DEEPFOCUS_KEY_ALIAS`, `DEEPFOCUS_STORE_PASSWORD`, `DEEPFOCUS_KEY_PASSWORD`,
and optionally `DEEPFOCUS_EXPECTED_CERT_SHA256` (pins the certificate; CI fails on mismatch).

```bash
cd ~/projects/zen-study-focus || exit 1
# one-time: create a NEW upload key outside the repo (keep a private offline copy)
keytool -genkeypair -keystore ~/deepfocus-upload.jks -alias upload -keyalg RSA -keysize 3072 -validity 9125
base64 -w0 ~/deepfocus-upload.jks | gh secret set DEEPFOCUS_KEYSTORE_B64
gh secret set DEEPFOCUS_KEY_ALIAS --body upload
gh secret set DEEPFOCUS_STORE_PASSWORD
gh secret set DEEPFOCUS_KEY_PASSWORD
keytool -list -v -keystore ~/deepfocus-upload.jks -alias upload | grep SHA256   # then:
gh secret set DEEPFOCUS_EXPECTED_CERT_SHA256 --body "<that SHA256>"
```

## The old `zenfocus2026.jks`

It was generated by the old workflow with a fixed, public password (`zenfocus2026`) and is still in
Git history (SHA-256 `F7:41:52:E4:...:F6:99:92`). Treat it as compromised. If Google Play already
registered it as the upload key, request an upload-key reset in Play Console
(Release > Setup > App signing) and register the new key above. Never reuse the old one.
