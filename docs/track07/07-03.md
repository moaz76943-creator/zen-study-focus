## Reproduction and smallest repair

The existing opt-in `createController` accepted a synchronous `persist` callback
returning `false`, changed its active locale and rendered a success-state change.
This is a latent API contract defect: no production call site of this controller
was found in the audited application. It is not evidence of observed Android data
loss. The controller now returns false before changing state or rendering when
the adapter explicitly returns false. Existing void-success callbacks and thrown
errors retain their previous behavior. Retry after rejection remains possible.
This synchronous callback contract does not add asynchronous persistence support.

No translation strings, central bindings, v21 keys, native bridge, AtomicFile,
shared app files, or user-authored content changed.
